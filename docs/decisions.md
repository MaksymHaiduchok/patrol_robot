# Журнал архітектурних рішень

## Етап 0 — скелет репозиторію (2026-11-08)

- Звичайний репозиторій з окремими папками без workspaces/Turborepo: кожен сервіс незалежний і запускається окремо, що відповідає модульній архітектурі (будь-який модуль можна замінити).
- web згенеровано `create-next-app` (Next.js 16, App Router, TypeScript, Tailwind 4), api — `@nestjs/cli` (NestJS 12, ESM, strict, Vitest), vision — `uv` (Python 3.12, FastAPI).
- vision має плоску структуру з `main.py` у корені, щоб запускатися як `uvicorn main:app`.
- api слухає порт 4000 за замовчуванням і має увімкнений CORS для web.
- robot і fake-robot поки лише з README і `.env.example`: їхній код — етапи 7–8.
- Секрети тільки в `.env` (у `.gitignore`), у репозиторії — `.env.example`.

## Етап 1 — відео в браузері (2026-11-08)

- Джерело відео задається `PHONE_STREAM_URL`: число — індекс локальної камери (`0` — камера Mac), рядок — URL MJPEG-стріму IP Webcam. Для розробки використовується камера Mac; для замірів (етап 10) — телефон на машинці, бо саме він є камерою робота.
- Кадри читаються в окремому потоці (`FrameGrabber`), зберігається лише останній кадр без черги: так стрім не накопичує затримку, якщо споживач повільніший за камеру.
- Кадр кодується в JPEG один раз у потоці захоплення, а `/stream` лише роздає готові байти — кількість глядачів не впливає на навантаження CPU.
- При втраті джерела потік автоматично перепідключається кожні 2 с; стан з'єднання і FPS видно в `/health`.
- У web відео показується звичайним `<img>`: браузер нативно відтворює `multipart/x-mixed-replace`, а `next/image` для стрімів не підходить (правило eslint `no-img-element` вимкнено).

## Панель оператора — каркас інтерфейсу (2026-11-08)

- Одна сторінка за зразком стрімінгових платформ: зліва керування (режим системи, авто/ручне, рух з клавіатури WASD/стрілками, швидкість, стоп/продовжити), по центру відео, під ним панель стану, справа стрічка алертів. Оператор бачить усе, не перемикаючи сторінок.
- Стан vision і FPS камери беруться з `GET /health` (опитування раз на 2 с); для цього у vision увімкнено CORS (`CORS_ORIGINS`).
- Кнопки керування поки змінюють лише локальний стан: відправка команд з'явиться разом з `OperatorGateway`/`RobotGateway` (етапи 4 і 7).
- MJPEG-стрім ніколи не завершується, тому uvicorn запускається з `--timeout-graceful-shutdown 1`, інакше перезапуск (`--reload`) зависав на відкритому з'єднанні браузера.
- Плеєр вважає стрім втраченим, якщо перший кадр не прийшов за 5 с, і пропонує перепідключитись.

## Перевірка розпізнавання облич до інтеграції (2026-11-08)

- Перед вбудовуванням у систему перевірено, чи достатньо якості YuNet + SFace (OpenCV Zoo), замість готових систем (Frigate + Double Take + CompreFace, студентські репо на YOLOv3/v5 + `face_recognition`/dlib). Готові системи — окремі NVR-продукти через Docker/MQTT, що не вписуються в архітектуру «vision лише детектує, api вирішує»; дрібні репо застарілі й без потокової обробки.
- Скрипт `vision/scripts/face_demo.py`: «свій» з однією фотографією впізнається з cosine similarity ≈ 0.75 при порозі 0.363; незнайоме обличчя позначається «чужим». Якості достатньо — використовуємо YuNet + SFace, як заплановано.
- Моделі завантажує `vision/scripts/download_models.py` у `vision/models/` (не комітиться). Фото для тесту лежать у `vision/faces_demo/` (не комітиться — біометричні дані).

## Етап 2 — детекція людей YOLO11n (2026-11-08)

- Дворівнева схема: YOLO11n шукає людину цілком (видно спиною, збоку, здалеку — коли обличчя ще не видно), а розпізнавання облич (етап 5) працюватиме лише всередині знайдених рамок. Для патрульного робота важливо зупинитись, щойно в кадрі людина, а не коли вона подивиться в камеру.
- Детекція працює в окремому потоці (`PersonDetector`) на останньому кадрі з частотою не більше `DETECTION_MAX_FPS` (10/с). Потік захоплення не чекає YOLO: на кожен кадр стріму малюються останні відомі рамки, тому відео лишається плавним (~30 FPS), а рамки оновлюються 10 разів на секунду.
- Пристрій `mps` (GPU Apple Silicon) з автоматичним fallback на `cpu`. Перший запуск прогріває модель (~8 с) до старту потоку, щоб перший реальний кадр не мав аномальної затримки.
- Перший замір (MacBook, `mps`, тестове зображення 810×1080): середній час інференсу ≈ 35 мс, детекція 9.9/с (обмежена лімітом 10/с).
- `GET /metrics`: FPS захоплення, FPS детекції, середній і максимальний час інференсу (по останніх 100 запусках), кількість людей у кадрі, пристрій.
- Ваги `yolo11n.pt` завантажуються скриптом `scripts/download_models.py` з офіційного репозиторію Ultralytics на Hugging Face у `vision/models/`: автозавантаження Ultralytics з GitHub Releases під час розробки віддавало 504.
